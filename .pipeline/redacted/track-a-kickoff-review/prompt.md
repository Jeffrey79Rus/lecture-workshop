# 교차검증 지시문 — Track A 킥오프 아젠다 리서치 (비식별 사본)

대상 파일: `target-track-a.html` (이 폴더 기준). 브라우저 없이 HTML 텍스트를 그대로 읽어 검토한다. 파일을 수정하지 않는다.

## 문서 배경
[주최사]가 [행사 시점]에 여는 제약·바이오 고객 대상 행사의 Track A(Strategy & Launch) 내부 킥오프 사전 자료다. Track A는 두 개 Round로 구성되며, Round 질문은 행사 기획서에서 이미 확정되어 있다.

- Round 1: "성장 기회는 어디에 있는가?" — 시장·환자·경쟁 환경 기반의 Growth Opportunity 발굴 (Where to play)
- Round 2: "성공적인 Launch를 어떻게 준비할 것인가?" — Cross-functional Readiness 및 Launch Operating Model

다른 Track의 영역은 다음과 같고, Track A와 겹치면 안 된다.
- Track B (Evidence & Access): Evidence 전략, Value Proposition, 급여·가격·접근성 실행
- Track C (Engagement & AI): HCP·환자 참여, Next-best Action, AI 기반 Commercial Performance 최적화
- 오전 플레너리 패널: "What Defines Commercial Launch Excellence?" (일반론)

문서는 ① 6개 트렌드(T1~T6) ② 후보 Client Challenge 5개(A~E)와 평가 매트릭스 ③ Key Takeaway 문안 3개 ④ 검증 결과·변경 로그로 구성된다. 추천안은 B(Round 1), C(Round 1→2 연결), A(Round 2, 고정 아젠다 'AI 에이전트의 확산')이며 D·E는 제외했다.

## 검토 관점 (우선순위 순)

1. **Round 부합성 (가장 중요).** 후보 A~E 각각이 배정된 Round의 질문에 실제로 답하는지 판정한다. 특히
   - B가 Round 1 "성장 기회는 어디에 있는가"에 답하는가, 아니면 '본사 설득 논리'로 흘러 Round 질문을 벗어나는가.
   - C를 "Round 1→2 연결"로 둔 것이 타당한가, 아니면 한 Round에 귀속시켜야 하는가. 두 Round에 걸치면 각 Round에서 무엇을 다루는지 명확한가.
   - A가 Round 2 "Launch를 어떻게 준비할 것인가"의 답인가, 아니면 'AI 도입' 자체가 주제가 되어 Round 질문을 대체하는가.
   - 제외한 D·E의 제외 사유가 Round 질문과 Track 경계 기준으로 타당한가.
   결과를 5행(A~E) × 4열(Round 1 부합 / Round 2 부합 / Track B·C 중복 위험 / 판정과 이유) 표로 먼저 제시한다. 부합 정도는 '부합 / 부분 부합 / 불부합'으로 쓴다.

2. **Track 경계.** 각 후보의 '논의 축'과 '하지 않을 것' 항목이 Track B·C·플레너리와 실제로 겹치지 않는지. 겹치는 문장을 인용하고 어느 Track의 영역인지 쓴다.

3. **논리.** (a) MECE·구조: 트렌드 6개의 분류, 후보 5개의 분류에 중복·누락이 있는가. 평가 매트릭스의 6개 기준이 서로 독립적인가. (b) 인과 비약: 트렌드 사실에서 시사점으로, 시사점에서 Client Challenge로 넘어갈 때 건너뛴 단계가 있는가. 반증조건이 실제로 해당 주장을 반증하는 조건인가. (c) 숫자·단위: 본문 안의 수치가 서로 모순되지 않는가(예: 같은 사실을 다른 수치로 적은 곳, 비율 합계, 환산). 매트릭스 합계를 재계산한다.

4. **Key Takeaway.** 문안 ①②③이 각 Round의 내용을 한 문장으로 대표하는가. 근거 트렌드가 그 문장을 떠받치는가. 더 강한 대안 문안이 있으면 1개씩 제안한다.

5. **사실 일관성(제한적).** 가린 항목(`[주최사]`, `[BU1]`, `[행사명]`, `[목표A]` 등)은 실명을 추측하지 말고 문서 내부 문맥의 일관성만 본다. 공개된 기업명·정부 제도·보고서 수치는 웹 확인이 가능하면 확인하고, 불가능하면 '확인 불가'로 표시한다. 문서의 검증 라벨([검증완료]/[부분검증])이 근거 수준과 맞게 붙었는지도 본다.

## 출력 형식
파일을 만들지 말고 표준 출력으로만 쓴다. 한국어.

1. 한 단락 총평 (추천안 B·C·A와 Round 배치에 동의하는지, 핵심 수정 1~2개).
2. Round 부합성 표 (관점 1).
3. 지적 사항 목록. 지적 사항마다 번호(C1, C2 …)·위치(섹션 번호와 문장 인용)·문제·근거·수정 제안을 쓴다. 중요도는 치명(결론·Round 배치·숫자 오류) / 중요(논리 비약·경계 침범·근거 부족) / 경미(표현)로 표시한다. 치명·중요를 먼저 쓴다.
4. 삭제하거나 합칠 것 (있으면).

규칙: 가린 이름의 실명을 추측하지 않는다. 문서 밖의 일반론을 길게 쓰지 않는다. 지적마다 반드시 원문을 인용한다.
